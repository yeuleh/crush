# 需求文档

## 介绍

本功能添加一个新的自定义 Gemini 提供商实现，使用纯 HTTP API 调用而不是现有的 genai 客户端库。custom-gemini 提供商将提供与当前 Gemini 提供商相同的功能，但通过直接 HTTP API 集成，提供对请求/响应处理的更多控制，并减少外部依赖。

## Requirements

### 需求 1

**用户故事：** 作为开发者，我希望使用一个通过 HTTP 直接与 Google Gemini API 通信的自定义 Gemini 提供商，以便我能更好地控制 API 交互并自定义实现，而不受 genai 客户端库的限制。

#### 验收标准

1. 当用户配置类型为 "custom-gemini" 的提供商时，系统应创建使用 HTTP API 调用的 CustomGeminiClient
2. 当自定义 Gemini 提供商初始化时，它应支持与现有 Gemini 提供商相同的基础 URL 配置
3. 当使用自定义 Gemini 提供商时，它应以与其他基于 HTTP 的提供商相同的方式使用 API 密钥进行身份验证
4. 当自定义 Gemini 提供商处理请求时，它应支持与现有 Gemini 提供商相同的所有模型类型和配置
5. 当系统配置了 HTTP 代理时，自定义 Gemini 提供商应能够通过系统代理发送 HTTP 请求

### 需求 2

**用户故事：** 作为用户，我希望自定义 Gemini 提供商支持流式和非流式响应，并能在流式不可用时自动降级，以便我可以在各种 API 环境下使用该提供商。

#### 验收标准

1. 当用户使用自定义 Gemini 提供商调用 SendMessages 时，系统应向 Gemini API 发出同步 HTTP 请求并返回完整响应
2. 当用户使用自定义 Gemini 提供商调用 StreamResponse 时，系统应首先尝试发出流式 HTTP 请求
3. 当流式请求成功时，系统应在接收到响应块时发出相应事件（EventContentStart、EventContentDelta、EventContentStop 和 EventComplete）
4. 当流式请求失败或不支持时，系统应自动降级到非流式请求并模拟流式事件序列
5. 当响应中存在工具调用时，系统应适当地发出 EventToolUseStart、EventToolUseDelta 和 EventToolUseStop 事件
6. 当使用降级模式时，系统应在日志中记录降级信息但不影响用户体验

### 需求 3

**用户故事：** 作为用户，我希望自定义 Gemini 提供商支持工具调用功能，以便我可以使用 Gemini API 的函数调用能力。

#### 验收标准

1. 当向自定义 Gemini 提供商提供工具时，它应将其转换为 Gemini API 函数声明格式
2. 当 Gemini API 返回函数调用时，系统应将其转换为内部 ToolCall 格式
3. 当在消息中提供工具结果时，系统应将其转换为 Gemini API 函数响应格式
4. 当进行函数调用时，系统应生成唯一的调用 ID 并维护适当的工具调用状态

### 需求 4

**用户故事：** 作为用户，我希望自定义 Gemini 提供商能够适当地处理错误和重试，以便临时问题不会导致永久性失败。

#### 验收标准

1. 当发生速率限制错误时，系统应实现带抖动的指数退避，直到最大重试次数
2. 当发生身份验证错误时，系统应尝试刷新 API 密钥并重试请求
3. 当发生网络错误时，系统应确定错误是否可重试并相应处理
4. 当达到最大重试次数时，系统应返回适当的错误消息

### 需求 5

**用户故事：** 作为开发者，我希望自定义 Gemini 提供商能够正确地在内部消息格式和 Gemini API 格式之间转换，以便正确支持所有消息类型。

#### 验收标准

1. 当处理包含文本内容的用户消息时，它们应被转换为 Gemini API 用户角色格式
2. 当处理包含二进制内容（图像）的用户消息时，它们应被转换为 Gemini API 内联数据格式
3. 当处理包含内容的助手消息时，它们应被转换为 Gemini API 模型角色格式
4. 当处理包含工具调用的助手消息时，它们应被转换为 Gemini API 函数调用格式
5. 当处理工具结果消息时，它们应被转换为 Gemini API 函数响应格式

### 需求 6

**用户故事：** 作为用户，我希望自定义 Gemini 提供商报告准确的令牌使用信息，以便我可以监控我的 API 消费。

#### 验收标准

1. 当 API 响应包含使用元数据时，系统应提取并报告输入令牌计数
2. 当 API 响应包含使用元数据时，系统应提取并报告输出令牌计数
3. 当 API 响应包含缓存内容信息时，系统应提取并报告缓存读取令牌
4. 当使用元数据不可用时，系统应为所有令牌计数返回零值

### 需求 7

**用户故事：** 作为系统管理员，我希望自定义 Gemini 提供商能够与现有提供商系统无缝集成，以便它可以作为当前 Gemini 提供商的直接替代品使用。

#### 验收标准

1. 当提供商类型设置为 "custom-gemini" 时，系统应实例化 CustomGeminiClient
2. 当创建自定义 Gemini 提供商时，它应实现与其他提供商相同的 Provider 接口
3. 当提供配置选项时，自定义 Gemini 提供商应遵守所有标准提供商选项（最大令牌数、系统消息等）
4. 当使用自定义 Gemini 提供商时，它应返回与其他提供商相同格式的响应
